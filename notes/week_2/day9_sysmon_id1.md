## 1. What is Sysmon?

Sysmon stands for **System Monitor**.

Once installed, Sysmon monitors system activity and records detailed events that can be viewed through Windows Event Viewer.

It provides additional telemetry about activity such as:

* Process creation and termination
* Network connections
* File creation
* Registry activity
* DNS queries
* Other system activity depending on the Sysmon configuration

This makes Sysmon useful for investigating activity on a Windows endpoint because it provides more detailed process and system information than relying only on basic Windows Security events.

## 2. Sysmon Event IDs Studied

| Event ID  | Meaning            | What I learned                                                                                                                                          |
| --------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1**     | Process Creation   | Records the creation of a process, including information such as the process image, parent process, command line, user, process identifiers and hashes. |
| **3**     | Network Connection | Records TCP/UDP network connections associated with processes, including information such as ports, protocols and addresses.                            |
| **5**     | Process Terminated | Records when a process terminates. This can contribute to understanding process timelines and when execution ended.                                     |
| **11**    | File Created       | Records when a file is created or overwritten.                                                                                                          |
| **12/13** | Registry Activity  | Records registry-related activity.                                                                                                                      |
| **22**    | DNS Query          | Records DNS queries made by processes.                                                                                                                  |

The main focus for today's investigation was **Event ID 1 — Process Creation**.

## 3. Sysmon Log Location

Sysmon events can be viewed in:

```text
Event Viewer
→ Applications and Services Logs
→ Microsoft
→ Windows
→ Sysmon
→ Operational
```

The Sysmon Operational log contains the telemetry generated by Sysmon.

## 4. Event ID 1 — Process Creation

Event ID 1 records the creation of a process.

Important fields include:

* Image
* Command Line
* User
* Process ID
* Process GUID
* Parent Image
* Hash

These fields provide context about what process was created, how it was launched, under which account, and which process launched it.

## 5. Detailed Event ID 1 Investigation

I generated normal activity on my Windows host and investigated a Notepad process creation event.

### Event information

**Time:**

```text
2026-09-19T11:37:58.5285648Z
```

**Event ID:**

```text
1
```

### Image

```text
C:\Program Files\WindowsApps\Microsoft.WindowsNotepad_11.2607.14.0_x64__8wekyb3d8bbwe\Notepad\Notepad.exe
```

The Image field shows the executable that was created.

In this case, the process was the Windows Notepad executable.

### Command Line

```text
C:\Program Files\WindowsApps\Microsoft.WindowsNotepad_11.2607.14.0_x64__8wekyb3d8bbwe\Notepad\Notepad.exe
```

The command line shows how the executable was launched.

In this event, the command line corresponds to the Notepad executable itself and does not contain additional arguments.

### User

```text
JEEVITHA\JEEVITHA
```

The process was associated with the `JEEVITHA` user account on the `JEEVITHA` machine/domain context shown by the event.

### Process ID

```text
9152
```

The PID identifies this particular running process instance.

### Process GUID

```text
{04d20fda-7415-6aae-6b06-00000000d501}
```

Sysmon provides a Process GUID that can be used as an additional identifier when correlating process-related telemetry.

### Parent Image

```text
C:\Windows\explorer.exe
```

The parent process was Windows Explorer.

This gives the relationship:

```text
explorer.exe
      ↓
Notepad.exe
```

This is consistent with launching Notepad through normal user interaction with the Windows desktop.

## 7. What Fields Would Help During an Investigation?

The fields that would be particularly useful when investigating a process include:

### Image

Shows which executable was launched and its location.

The executable's path can provide important context. An expected Windows executable in its normal system directory is different from an executable with the same or similar name running from an unusual location.

### Command Line

Shows how the process was launched and whether additional arguments were supplied.

This can provide important context that cannot be obtained from the executable name alone.

### Parent Image

Shows which process created the process being investigated.

This helps reconstruct how execution occurred.

### User

Shows which account was associated with the process.

This helps determine whether the process was running under an expected account or context.

### Process ID

Provides an identifier for the process instance.

### Process GUID

Provides another identifier that can be useful when correlating process-related events.

### Hash

Provides a cryptographic fingerprint of the executable observed by Sysmon.

      ↓

The process was created under the `JEEVITHA\JEEVITHA` account, had PID `9152`, and was launched from the expected WindowsApps Notepad installation path.

## 9. Important Lesson

A process name or Event ID by itself does not determine whether activity is suspicious.

For example:

```text
powershell.exe
```

does not automatically mean malicious activity.

Instead, an investigation should consider multiple pieces of evidence:

```text
Process
   ↓
Image/path
   ↓
Command line
   ↓
Parent process
   ↓
User
   ↓
Timing
   ↓
Other related telemetry
```

The surrounding context determines how the event should be interpreted.

## 10. What I Learned

1. Sysmon provides detailed endpoint telemetry that can be used for Windows investigation.
2. Event ID 1 records process creation and provides several useful fields for investigation.
3. The Image field identifies the executable that was created, while Parent Image identifies the process that launched it.
4. Command-line information provides additional context about how a process was executed.
5. Process IDs and Process GUIDs can help identify and correlate process activity.
6. Normal Windows activity can generate multiple process-creation events within a very short period.
7. An event should not automatically be considered suspicious simply because it involves a privileged account, a system process, or a particular executable.
8. Understanding the surrounding context and correlating evidence is more useful than judging an event in isolation.
